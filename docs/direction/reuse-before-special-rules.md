# Reuse before special rules

Decided 2026-10-18.

## What was decided

Every part of the pipeline is built from the moves and combos that already
exist (Gather, Act, Listen, Draft, Check, Judge; gate, remember, refine, ask,
spawn). A new special rule is the last resort, not the first.

- **Each part gets three questions before it is rebuilt:**
  - Do we need it at all?
  - Is it actually something else we already have?
  - Does it belong in another place?
- **Side parts get the same care as the main loop.** Milestones, campaigns,
  priorities and labels were added beside today's loop, mostly as opinion.
  They go through the three questions like every stage does.
- **Moving a part into code is how it gets reused.** Once a part is a machine
  or a move, another stage can use it as it is.

## Why

- A part that is reused carries its proof with it. A check that already caught
  real problems in review is worth more in the plan stage than a new rule
  written for the plan stage.
- Special rules grew from single incidents in today's fabrika, and each one
  carried its writer's taste. Nobody went back to ask whether they still fit
  together.

## What it means for the work

- Before adding a field, label, stage or rule, name the existing move or combo
  it could be. Write down why none fits if you add something new.
- A write-up that adds a special rule says which of the three questions it
  failed.

## What would change it

A part that, rebuilt from existing moves, needs more code and catches less
than a special rule for it did.
