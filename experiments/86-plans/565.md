# Plan: code-graph readAllowance refuses a driving adapter whose read decides nothing (#565)

Today `readAllowance` only excuses B8 when the driving file also imports, at runtime, a library of a `decidedBy` type. A thin read handler that only parses input and calls a listed read-only driven file imports no such library, so it stays B8. The only ways round that are moving the handler out of the feature, adding a ledger baseline, or declaring a `decidedBy` type that means nothing. After the fix, a scope may leave out `decidedBy`. B8 is then excused for any driving file that imports a listed driven file, and the write rule still applies. A scope that declares `decidedBy` gates exactly as it does today, and an empty `decidedBy` is still refused.

Size: 1 task, 11 criteria, 880 words.

## Open questions

1. Should leaving out decidedBy and writing an empty decidedBy list mean different things?
   - Options: Missing means 'no decision proxy, excuse any listed read'; an empty list stays refused (exit 2) as #525 pinned it / Treat an empty list the same as missing, and drop the #525 refusal
   - Lean: Keep them apart: missing excuses any listed read, empty is still refused.
   - Why: An empty list is more likely a mistake than a choice, and #525 pinned refusing it on purpose. Leaving the key out is a clear opt-in. The criterion about the empty-list refusal depends on this choice.
