## In plain words

`pnpm --filter @demlik/tea run api:ratchet` is the script CI uses to check that a change to tea's published API comes with the right changeset. CI gives it a commit to compare against. Run by hand without one, it compares nothing and still ends green, so a contributor checking before a push reads "no changeset needed" when nothing was checked. We would make the script never end green without having compared against a commit it names.

## Scope

Read at `origin/main` (6780a06) and reproduced there: with `TEA_API_BASE` unset the script prints `Tests  14 passed | 1 skipped (15)` and exits 0.

Where it is:

- `packages/tea/package.json`: `"api:ratchet": "vitest run src/api-ratchet/api-ratchet.test.ts"`. The script is the bare test file.
- `packages/tea/src/api-ratchet/api-ratchet.test.ts`: `const BASE = process.env.TEA_API_BASE`. Three suites (`api map`, `bump policy`, `verdict text`, 14 tests) are `describe.runIf(BASE === undefined)`. The one check, `published API against TEA_API_BASE`, is `describe.runIf(BASE !== undefined)`. With no base the check is the one skipped test.
- `packages/tea/src/api-ratchet/ratchet.ts`: `runApiRatchet(base)` runs the diff and `renderVerdict` prints the base's short hash on a pass and on a miss.
- `.github/workflows/build.yaml`: the step "Published API changes carry the changeset their tier asks for" sets `TEA_API_BASE: HEAD^1` for that step only. The next step, `pnpm test`, runs the same test file with no base, which is how the 14 mechanism tests run in CI.

The same file does two jobs keyed on one variable, so the script cannot tell "a person ran the check and forgot the base" from "the test suite is running the mechanism tests". The fix has to tell those two apart.

Two shapes meet the criteria, and the issue names both:

1. The script refuses when no base is given, and says how to give one.
2. The script picks a base itself (for example the merge base with `origin/main`) and prints which one it used.

- [ ] No run of the script exits 0 without printing the commit it compared against. A test proves the no-base case without running the slow compiler diff: it starts the script with `TEA_API_BASE` removed from the environment and asserts on the exit code and the output.
- [ ] `pnpm test` from the root, and `pnpm --filter @demlik/tea test`, still run the 14 mechanism tests in `api map`, `bump policy` and `verdict text` with `TEA_API_BASE` unset, and still pass. The new refusal or default must not fire inside the plain test run, and the plain test run must not start the compiler diff.
- [ ] CI is unchanged in what it checks: the `build.yaml` step with `TEA_API_BASE: HEAD^1` still diffs against that commit, fails on a miss with the same miss text, and prints the same one-line pass.
- [ ] A base the script cannot resolve (an unknown revision, or a default it could not compute, such as no `origin/main` in a shallow clone) exits non-zero and says which base it tried. It never falls back to the green no-check run.
- [ ] The header comment of `api-ratchet.test.ts` and the comment above the `build.yaml` step describe what the script now does with no base.
- [ ] `pnpm typecheck && pnpm lint && pnpm test` pass from the root.

### No-gos

- No change to the bump policy, the API map, the diff, or the verdict text of a miss (`@demlik/code-graph/api` and `policy.ts` stay as they are).
- No changeset: nothing tea publishes changes.
- A removed export subpath that the ratchet does not see is #622, not this.
