## In plain words

When code-graph's API check (`--api-policy`) crashes, it ends with exit code 1, the same code it uses for "a published name is missing its changeset". A CI job that reads only the exit code can't tell a crash from a real miss, and a person sees a stack trace where they expect a verdict. We'd catch the crash, print one line, and exit with a code of its own.

## What happens

`packages/code-graph/src/index.ts` starts the `--api` mode with `void apiRun.then(exitWith)` and no rejection handler. `runApiView` in `packages/code-graph/src/api/cli.ts` turns an `ApiInputError` into exit 2 and rethrows everything else. So any other error rejects that promise with nothing to catch it, and Node prints the stack and exits 1.

`packages/code-graph/SPEC.md` §13.6 gives the ratchet's exits as 0 pass, 1 miss, 2 refused input. A crash is none of those and should not read as one.
